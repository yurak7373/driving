# 프로젝트 구조

| 경로 | 책임 | Phase 00 상태 |
| --- | --- | --- |
| `src/core/` | 게임 공통 시스템 | 화면 크기와 픽셀 비율 계산 |
| `src/vehicles/` | 차량 모델과 차량 제어 | 폴더 준비 |
| `src/physics/` | 차량 물리와 충돌 | 폴더 준비 |
| `src/input/` | 장치 입력을 공통 동작으로 변환 | 키보드와 화면 버튼 처리 |
| `src/camera/` | 카메라 위치와 시점 | 사선 및 위에서 보는 시점 |
| `src/ui/` | 화면 조작 요소와 상태 표시 | 렌더링 상태, 시점, 좌표 |
| `src/scenes/` | 게임 장면과 개발 시험 장면 | 시험 장면 렌더링과 상태 |
| `src/debug/` | 개발자 디버그 도구 | 폴더 준비 |
| `tests/` | 단위·통합·브라우저 테스트 | Vitest와 Playwright 테스트 |
| `docs/` | 개발과 검수 문서 | 구조, 검수 방법, 개발 기록과 결과 |

`src/main.ts`가 입력, 상태, 카메라, 렌더러와 UI를 연결합니다. 키보드와 화면 버튼은 같은 동작을 전달합니다. 순수 상태 갱신 함수가 표식 좌표와 시점을 계산하고, Three.js와 화면 UI는 그 상태를 표시합니다. 창 크기가 바뀌면 카메라 종횡비와 렌더링 크기를 갱신합니다.

현재 Three.js 장면에서 움직이는 물체는 테스트용 표식입니다. 차량 상태, 제어, 물리와 3D 버스 모델은 후속 단계의 구현 대상입니다.

카메라는 표식의 3D 경계 상자를 이동 가능 범위만큼 확장해 관찰 범위를 계산합니다. 캔버스가 좁아지면 두 시점 모두 이 범위가 들어오도록 카메라를 뒤로 이동합니다. 크기나 시점이 바뀌어도 표식 좌표를 유지합니다. 브라우저 검사에 사용하는 투영 범위는 렌더에 사용한 표식과 카메라에서 계산합니다.

Phase 01에서 차량 모델을 붙일 때 장면 시작·종료와 차량 교체 경로를 정의합니다. 반복 전환 시 이벤트 리스너, 렌더러 및 모델·텍스처의 소유권과 해제 시점을 명시합니다. 현재 시험 장면은 페이지당 한 번 시작하며, 이 요구사항은 반복적인 장면과 모델 교체를 위한 확장 준비입니다.

Phase 02~03에서는 지속 가속·제동·조향, 복수 키·멀티터치·자이로를 공통 차량 입력으로 처리합니다. 장치별 우선순위와 입력 합성 규칙을 정의하고, 포커스 상실이나 터치 취소 때 입력을 초기화합니다.
