`src/main.ts`가 입력, 상태, 카메라, 렌더러와 UI를 연결합니다. 키보드와 화면 버튼은 같은 동작을 전달합니다. 순수 상태 갱신 함수가 표식 좌표와 시점을 계산하고, Three.js와 화면 UI는 그 상태를 표시합니다. 창 크기가 바뀌면 카메라 종횡비와 렌더링 크기를 갱신합니다.

기존 시험 장면의 물체는 노란색 표식입니다. 버스 외부 모델은 별도 관찰 장면에서 시작하며, 전륜 조향과 바퀴 회전은 검수용 자세를 적용합니다.

카메라는 표식의 3D 경계 상자를 이동 가능 범위만큼 확장해 관찰 범위를 계산합니다. 캔버스가 좁아지면 두 시점 모두 이 범위가 들어오도록 카메라를 뒤로 이동합니다. 크기나 시점이 바뀌어도 표식 좌표를 유지합니다. 브라우저 검사에 사용하는 투영 범위는 렌더에 사용한 표식과 카메라에서 계산합니다.

## Phase 01-A 버스 외형

- `src/vehicles/bus/busConfig.ts`는 게임용 제원과 도색 설정을 보관합니다. 차량 원점은 차체 길이·폭 중심의 지면입니다. 단위는 미터입니다. 전방 +Z, 위쪽 +Y에서 벡터 외적으로 운전자 기준 오른쪽 −X를 계산합니다. 왼쪽은 +X입니다. 차체, 바퀴, 미러, 전후 조명과 관찰 시점에 같은 좌우 기준을 씁니다. 양의 전륜 조향각은 운전자 기준 왼쪽 회전입니다. 11.0 × 2.5m는 차체 기준이며 미러와 외부 돌출 부품은 제외합니다. 전고 3.2m는 에어컨 등 지붕 장치를 포함합니다. 전륜 중심은 Z=+3.1m, 후륜 중심은 Z=-2.4m입니다.
- `busVisual.ts`는 `BusRoot` 아래 외형, 차축, 도어와 앵커를 조립합니다. 위치·회전·조향각·바퀴 각도를 받아 외형에 적용합니다. 도색은 기존 재질의 색만 바꿉니다. 조향 피벗과 바퀴 회전은 별도 노드입니다.
- `InteriorAnchors`에는 운전석·대시보드·핸들·승하차 지점·통로·좌석 영역·손잡이·조명을, `CameraAnchors`에는 운전자·승객·좌우 미러·후방 카메라 위치를 둡니다. 앵커의 진행 방향은 로컬 +Z입니다. 실제 Three.js 카메라 연결 시 카메라의 시선 축인 로컬 -Z를 고려하세요. `FrontDoor`와 `MiddleDoor`는 각 문짝 피벗과 유리 노드를 가집니다.
- 관찰 UI는 브라우저 입력을 `busPreviewState.ts`의 동작으로 보내고, 갱신된 상태를 모델에 전달합니다. 카메라는 실제 모델 경계로 초기 시야를 계산합니다. 창 크기를 바꿀 때 방향과 상대 확대 비율을 유지합니다.

## 장면과 자원 수명

`src/main.ts`는 해시 변경에서 현재 장면을 먼저 종료한 후 다음 장면을 시작합니다. 종료 함수는 입력 구독과 화면 크기 관찰을 해제합니다. 버스 카메라는 이벤트가 있을 때 렌더링하며 OrbitControls도 종료 시 해제합니다. 각 장면은 자신이 만든 렌더러와 WebGL 컨텍스트를 종료합니다. 재진입 시 새 캔버스를 사용하며, HMR에서도 같은 종료 함수를 호출합니다.

버스는 자신이 만든 Geometry와 Material을 공유해 사용한 뒤 각각 한 번씩 해제합니다. LED·번호판·차량 번호 텍스처는 관찰 장면 소유이며 모델은 재질에서 빌려 씁니다. 장면의 `replaceModel()`은 이전 차량을 제거하고 모델 경계를 갱신합니다. 관찰 장면 종료 시 차량, 장면 바닥·그리드, 텍스처와 렌더러를 정리합니다.

LED 행선지에는 Noto Sans KR의 기본 행선지와 숫자 서브셋을 포함합니다. 다른 문자는 사용 가능한 시스템 글꼴로 표시됩니다. [글꼴 출처](https://fonts.google.com/noto/specimen/Noto+Sans+KR) · [SIL Open Font License 1.1](../public/licenses/OFL-NotoSansKR.txt)

## 후속 단계

Phase 01-B에서는 운전석과 실내, Phase 01-C에서는 문 개폐를 연결합니다. 실제 미러 영상, 차량 물리, 엔진과 변속기, 승객 AI, 도시·노선 운행 및 멀티플레이는 후속 범위입니다.

Phase 02~03에서는 지속 가속·제동·조향, 복수 키·멀티터치·자이로를 공통 차량 입력으로 처리합니다. 장치별 우선순위와 입력 합성 규칙을 정의하고, 포커스 상실이나 터치 취소 때 입력을 초기화합니다.

### PHASE 01-B 이후 필수 항목

- **A-04** · 활성 차량 참조를 한 곳에서 관리합니다. 모델 교체 시 카메라 중심과 최소·최대 거리, 정보 패널, 도색 대상, 차량 기준점을 새 모델에 맞추고 기존 자원을 해제합니다. 크기와 원점이 다른 모델로 교체하는 테스트를 추가합니다.
- **A-05** · 초기화를 단계별로 관리하고 예외가 나면 생성한 렌더러, Geometry, Material, Texture, 이벤트와 관찰자를 정리합니다. LED·텍스처 실패 주입 후 표식 화면 복귀를 테스트합니다.
- **A-06** · 좌석·손잡이 등 반복 부품을 추가할 때 공유 자산과 InstancedMesh를 검토합니다. 감사 기준은 Draw Calls 399, 삼각형 42,044개, 렌더러 Geometry 171개, Texture 3개, 광원 3개입니다. 실제 모바일 FPS는 미검증이며, 외형과 필수 부품 식별 정보를 성능 검토에서 유지합니다.
